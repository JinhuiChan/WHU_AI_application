## 0. 版本演进：V2 的哪些结论被推翻

| V2 结论 | V3 修正 | 依据 |
|---|---|---|
| 角色分七类 | **收敛为三类用户**：学生／老师／管理员，权限差异靠"细分角色 + 阶段"实现 | 补充需求「用户登录分成三类」 |
| 指导老师不设线上节点 | **老师有"确认指导关系"动作**（轻量，不进审批链） | 「老师：查看所指导项目信息、确认指导关系」 |
| 领款人是独立信息块 | **领款人是团队成员上的一个开关**，勾选后才要求补全银行信息 | 截图「团队成员弹窗内 奖金领款人 开关」 |
| 窗口由状态自动触发 | **管理员统一设置时间窗口**为主；状态切换时的默认窗口作为兜底 | 「管理员可设置统一的时间参数」 |
| 统计看板放二期 | **统计看板进首期**（学院报名人数/项目数、赛道分布） | FR 3.4 |
| 不做奖项 | **奖项录入进首期**（金/银/铜，变更留痕），仍**不做评审打分** | FR 3.4 |
| 一致性比对为二期自研 | **省赛阶段接百度 OCR** 做一致性审查，首期即需 | FR 3.5 |
| 导出=正式表 | **导出分两类**：①可打印盖章的报名表 ②可本地二次编辑的数据表 | FR 3.2 + 3.3 |

## 1. 定目标

### 1.1 一句话

> **用一个平台接管全校科创赛事的报名与审核：学生按真实表单填完、队长按统一时间窗口管人和表、老师确认指导关系、管理员批量审核与流转，盖章件回传后全队可下载、管理员可批量打包；省赛阶段用 OCR 对盖章件做"填报 vs 扫描件"的一致性核对。**

### 1.2 成功标准

| # | 标准 | 核查 |
|---|---|---|
| S1 | 报名表单字段与截图逐项一致，学号/工号可检索带出 | 录入 1 个项目核对全部字段 |
| S2 | 队长在窗口内可增删改成员、调顺序；窗口关闭后前端锁定，只能提交申请 | 改系统时间验证锁定 |
| S3 | 任何变更在后台可查"谁、何时、改了什么的旧值与新值" | 抽 3 条日志核对前后值 |
| S4 | 队员可下载本队报名表打印；回传盖章件后，负责人可下载本队最终版；管理员可批量打包 | 走完一遍闭环并解压检查 |
| S5 | 导入支持 Excel/Word/PDF，按阶段绑定模板；导入前显示字段映射与逐行校验 | 用二课导出文件实测 |
| S6 | 导出可勾选字段与顺序，生成的 Excel 与"二课导出数据"格式可对齐 | 与 27 字段模板对照 |
| S7 | OCR 一致性审查输出"一致/不一致/人工复核"+ 差异字段清单，不做内容评价 | 用含错字的盖章件实测 |
| S8 | AI 问答可基于管理员上传的资料回答，答不出时不编造 | 问库内/库外各 3 题 |

## 2. 用户与角色

### 2.1 三类用户

| 用户 | 能做什么 | 不能做什么 |
|---|---|---|
| **学生** | 注册登录；创建/报名项目；**队长**管理团队（增删改成员、调整顺序，受时间窗口限制）；维护指导老师与领款人；上传盖章件；下载本队最终版；下载本队数据表 | 不能看别队数据；不能在窗口外改信息（须申请） |
| **老师** | 查看所指导项目信息；**确认指导关系**（同意/拒绝）；下载所指导项目的报名表 | 不能改学生填报内容；不参与审批链 |
| **管理员** | 审核报名；发布通知与开放报名入口；批量导入赛事；全局配置（赛道层级、模板、字段）；修改历史数据（留痕）；维护动态知识库与 AI 规则；系统安全设置；奖项录入；批量打包下载 | —（最高权限，但所有操作必须留痕） |

### 2.2 学生内部的三个位置

| 位置 | 权限 |
|---|---|
| 队长（项目负责人） | 创建项目、提交报名、管团队、指定第二/第三负责人、下载最终版 |
| 第二/第三负责人 | 队长失联时的后备；可发起变更、可下载最终版；不可删除项目 |
| 普通队员 | 查看本人登记信息并确认；可下载本队报名表；不可改任何人信息 |

### 2.3 阶段 × 可改范围

| 阶段 | 项目名称/赛道 | 成员增删与顺序 | 指导老师 | 领款人 |
|---|---|---|---|---|
| 报名窗口开放期 | 队长可直接改（留痕） | 可直接改（留痕） | 可直接改 | 可直接改 |
| 提交后待审核 | 冻结 | 冻结 | 冻结 | 冻结 |
| 校赛进行中 | 需申请（学院审） | 需申请（学院审） | 需申请 | 需申请（校级审） |
| 省赛（窗口期） | 可改（留痕） | 可改（留痕） | 可改 | 需申请（校级审） |
| 国赛 | 冻结 | 冻结 | 冻结 | 冻结（校级特批除外） |

### 3.4 奖金领款人（报名阶段即确定）

规则（来自样表填写说明 + 界面提示文案）：

1. 领款人**原则上是项目负责人**；也可由某位成员担任。
2. 界面上是**成员行上的一个开关**，全队**只能有一个"是"**；勾选新的会取消旧的。
3. 领款人若**已绑定校园卡银行账户**（智慧珞珈），只需学号；
4. 若**未绑定**，补填：学习/工作单位、联系电话、**身份证号**、**银行卡号**、**开户行（含支行）**、**开户人姓名**。
5. 前端提供奖金说明文案（发放周期约赛后 1–1.5 年、谨慎选定、开户行查询网址等）。

## 4. 赛事配置（FR 3.1）

### 4.1 层级结构

```
赛事系列（大挑 / 小挑 / 国创赛 / 百珈争创…）
  └─ 届次（2026）
      └─ 赛道
          ├─ 国创赛·高教主赛道
          │    ├─ 国内项目
          │    └─ 海外项目      ← 需体现从属层级
          ├─ 国创赛·青年红色筑梦之旅赛道
          └─ 国创赛·产业赛道
              ├─ 企业命题组（再选类别 + 命题名称 + 命题企业）
              └─ 成果转化组
      └─ 阶段（校赛 / 省赛 / 国赛）
```

**要求**：层级可从后台配置（新增赛事/赛道/组别/类别），不写死；**国创赛高教主赛道必须有"国内项目/海外项目"这一层**。

### 4.2 全局信息与历史变更

- 总管理员可改赛事名称、届次、阶段名称等全局信息。
- 每次修改写 `ConfigChangeLog`：操作人、时间、字段、旧值、新值。
- 被引用中的赛事（已有报名数据）改名时，提示"将影响 N 个项目的显示"。

### 4.3 统一操作时间窗口

- 管理员设置**统一的起止时间**（可按阶段分别设置：报名窗口、省赛修改窗口）。
- 窗口内：队长可自由改项目名称、成员、顺序。
- 窗口外：前端锁定，只能提交变更申请。
- **兜底**：状态切换（校赛→省赛）时，若管理员未设置窗口，系统按默认 7 天开窗，并在后台提示"使用了默认窗口"。

## 5. 数据导入（FR 3.2）

### 5.1 支持格式与规则

| 项 | 要求 |
|---|---|
| 格式 | **Excel（.xlsx/.xls）、Word（.docx）、PDF** |
| 模板绑定 | 按**阶段**绑定模板：校赛模板、省赛模板各自独立；**同阶段模板格式必须严格一致** |

## 6. 导出（FR 3.2 + 3.3）

### 6.1 两类导出，不要混为一谈

| 类型 | 用途 | 形态 | 谁可导出 |
|---|---|---|---|
| **A. 报名表（打印件）** | 打印、签字、盖学院党委章 | 按样表排版的表格（Excel/PDF），含签字位与公章位 | 队员、队长、老师（所指导项目）、管理员 |
| **B. 数据表（二次编辑）** | 交上级、做统计、二次加工 | 可勾选字段与顺序的**纯数据 Excel** | 队长（本队）、管理员（全校） |

> 明确边界（需求原文）：**不在网页端提供在线表格编辑，也不提供 AI 辅助填表**；导出后由用户在本地编辑。

### 6.2 自定义导出

- 勾选字段（默认全选 / 按模板预设）
- 调整顺序（拖拽或上下移）
- 选择模板（校赛/省赛/自定义）
- 导出格式：.xlsx
- 导出前校验：必填字段是否有空值（提示，不阻断）
- **每次导出记 `ExportRecord`**：导出人、字段集、行数、时间、水印编号

### 6.3 敏感字段处理

- 页面一律脱敏（身份证、银行卡显示后四位）。
- 数据表导出：默认脱敏；**勾选"含完整银行信息"需二次确认**，且仅队长（本队）与管理员可用，文件带水印。

## 7. 盖章闭环（FR 3.3）

```
① 队员/队长 下载报名表（A 类） → ② 线下打印、指导老师签字、学院党委盖章
→ ③ 任一队员上传扫描件（PDF/JPG/PNG，≤20MB） → ④ 队长/负责人 下载"本队最终版（已盖章）"
→ ⑤ 管理员 可单个或批量打包（zip）下载全校最终版
```

| 规则 | 说明 |
|---|---|
| 上传权限 | 本队任一成员可上传；上传后可替换（留旧版，可回溯） |
| 最终版标识 | 以"最后上传且未被驳回"的盖章件为最终版 |
| 批量打包 | 管理员按赛事/阶段/学院筛选后打包，**单次 ≤100 个项目、总量 ≤500MB**；文件名规范：`赛事_阶段_学院_项目名_队长_第N版.pdf`；超限提示分批；失败项生成清单可导出 |
| 未上传提醒 | 截止前 3 天、1 天各提醒一次（站内 + 邮件） |
| 状态联动 | "未上传盖章件即材料不齐"为**管理员可开关**，默认关闭 |

## 8. 审核流转、奖项与看板（FR 3.4）

### 8.1 审核

- 列表即第 5.3 的 27 列，支持按赛事/阶段/学院/状态/赛道筛选与关键词搜索。
- **两级审核**：学院审 → 校级终审；**驳回必填理由**。
- 行内可看详情：基本信息、指导老师、成员、作品、盖章件、变更历史。
- 批量操作：批量通过、批量驳回（需同一理由）。

### 8.2 状态流转

- 勾选多个项目 → "流转到下一阶段"（校赛→省赛→国赛）；或按名单**批量导入晋级结果**。
- 批量前**预检**：学号不存在、状态不允许、重复晋级 → 逐行报错。
- 支持整批回滚（回滚留痕）。

### 8.3 奖项管理

- 录入金/银/铜（及优秀奖）等；可随时变更；**所有变更留痕**（旧值/新值/操作人/时间）。
- 奖项数据进入看板与导出。

### 8.4 统计看板

- 各学院报名项目数、参与人数（去重）
- 各赛道项目分布
- 各阶段项目数
- 奖项分布
- 点击任一数字可下钻到项目列表

## 9. OCR 一致性审查（FR 3.5）

### 9.1 定位

**只做"填报信息 vs 盖章件扫描件"的文字一致性核对，绝不做内容评审。**

### 9.2 流程

```
省赛阶段 → 管理员选中项目 → 触发审查
→ 调用百度 OCR（最新接口）识别盖章件/证明材料文字
→ 与系统填报字段比对（项目名称、负责人、成员姓名、指导老师、赛道）
→ 输出结论：一致 / 不一致 / 人工复核
```

### 9.3 输出与边界

- 每条给出**差异字段清单**：字段名、系统值、扫描件值、相似度。
- 名称类差异用编辑距离/包含关系判定（如"智能巡检系统"vs"基于多模态的智能巡检系统"记为"包含"而非"不一致"）。
- 结论**仅为提示**，不自动改状态、不阻断流转。
- 人工复核后勾选"以系统为准/以扫描件为准/忽略"，留痕。

### 9.4 技术约束

- OCR 接口密钥由管理员在"系统设置"维护，不写死在前端。
- 单次审查异步执行，页面显示进度；批量审查排队。
- 识别失败（扫描模糊、倾斜）直接归入"人工复核"，不硬判。

## 10. AI 问答（FR 3.5）

- 界面固定入口（右侧悬浮或独立页）：学生/老师/管理员均可问。
- **知识源**：管理员上传的通知、规则、填写说明、常见问题（动态知识库），支持增删改与生效时间。
- 作答规则：**命中则答并注明来源文件与章节；未命中固定回复"暂无权威口径，请联系赛事办"**并给出联系方式，**禁止编造**。
- 不回答与赛事无关的问题。
- 不做内容评审、不做评分建议。

## 11. 安全与接口（FR 3.6）

| 项 | 要求 |
|---|---|
| 文件白名单 | 仅 .xlsx/.xls/.docx/.pdf/.jpg/.png；校验扩展名 + MIME + 文件头 |
| 敏感数据 | 身份证、银行卡**应用层加密**（密钥独立，不入库）；页面脱敏；读取留痕 |
| 防重放 | 关键写接口带时间戳 + 随机数 + 签名；同一 token 重复提交直接拒绝 |
| 限流 | 按账号 + IP；导出限次；登录失败 5 次锁定 10 分钟 |
| 防爬 | 登录墙、`noindex`、敏感页 `no-store`、异常访问告警 |
| 审计 | 全部写操作 + 敏感读操作 + 导出操作留痕，保留 ≥3 年 |
| 统一认证 | 预留 CAS/OAuth 适配层（`external_id` + Provider 可切换），首期用自建账号（学号 + 手机号） |

## 16. 风险与待确认

### 16.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 首期 13 项偏重 | 延期 | 砍变更审批流（先用窗口+管理员改）、OCR/AI 已后置 |
| 报名高峰无退路（直接替代） | 事故 | 压测 + 只保提交的降级 + 延期窗口开关 |
| 领款人银行卡在报名期即采集 | 隐私面扩大 | 加密 + 脱敏 + 读取留痕 + 导出水印 |
| Word/PDF 解析不稳 | 导入失败 | 解析结果必须人工确认；以 Excel 为主通道 |
| 二课 27 字段的历史脏数据 | 迁移后对不上 | 导入校验报告 + 失败行导出修正 |
| 老师不点"确认指导关系" | 流程停滞 | 做成"提醒 + 可代确认（留痕）"，不作强前置 |

### 16.2 已决事项（开发期由 Lead 决定，事后可推翻）

| # | 争议点 | 决定 | 理由 |
|---|---|---|---|
| 1 | "作品"字段是什么 | **作品 = 上传文件（单个主文件，支持 PDF/ZIP/图片/外链视频）；作品形式 = 下拉字典（实物/软件/报告/视频/其他）；类别/组别 = 与赛道级联的下拉** | 报名阶段作品多为文档；文件+外链覆盖 95% 情况，不必做多文件复杂模型 |
| 2 | 申报单位 vs 培养单位 | **两个独立字段，默认带出同一值，允许不同；不同时用黄色提示"与学籍所在单位不一致"，不阻断提交** | 跨学院组队、实验室挂靠很常见，硬性一致会逼学生造假 |
| 3 | 老师确认是否强前置 | **不做强前置**。未确认项目照常提交与审核，但管理员列表标"指导关系未确认"红标，导出报名表时提示"指导老师尚未线上确认" | 强前置会在截止日卡死大量项目，而老师里总有不登录的 |
| 4 | 评分字段 | **管理员可见（只读，来自历史导入）；学生端完全隐藏；新提交项目无评分字段** | 二课历史数据里有分数，丢了就无法对账；但绝不能被理解为"本系统在评审" |
| 5 | 批量打包下载 | **单次 ≤100 个项目、总量 ≤500MB**；命名 `赛事_阶段_学院_项目名_队长_第N版.pdf`；超限提示分批；失败项生成清单可导出 | 一次打包全校会拖垮服务器；分批更安全 |
| 6 | 变更申请首期形态 | **保留轻量版**：申请单（选字段 + 填理由 + 佐证）→ 学院审 → 校级审，复用审核模块组件与审批状态机；**不做**"按字段类型自动路由"的复杂矩阵（先用申请人手选变更类型） | 12 题已确认"变更"是首期核心；做成轻量版即可，工期不足时降级为"管理员代改并留痕" |
