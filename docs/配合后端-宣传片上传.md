# 宣传片上传：需要后端配合的两处改动

前端已经做完（管理员在赛事详情页的「宣传片与赛事解读」里选文件、填标题、预览、删除；学生端赛事简介页自动把 `kind = VIDEO` 或视频后缀的附件渲染成播放器）。

但**后端附件接口现在会把视频挡掉**，不是前端能绕过的：

`app/api/admin/competitions/[id]/attachments/route.ts`

1. `kind` 白名单只允许三个值：
   ```ts
   if (kind !== "NOTICE" && kind !== "RULE" && kind !== "TEMPLATE") return apiError(422, "文件类型不正确");
   ```
   → 需要放开 `VIDEO`。

2. 扩展名 / MIME / 文件头三道校验都只认识文档和图片：
   ```ts
   type Extension = "pdf" | "docx" | "doc" | "xlsx" | "jpg" | "jpeg" | "png" | "txt";
   ```
   → 需要加 `mp4`（`video/mp4`）和 `webm`（`video/webm`），并补文件头校验：
   - mp4：第 4–7 字节是 `ftyp`（`0x66 0x74 0x79 0x70`）
   - webm：开头是 `0x1A 0x45 0xDF 0xA3`

改完这两处，前端不需要再动：上传走同一个接口，返回成功后页面刷新，播放器就出现了。

## 还有一个容量问题

接口现在写死 `maxFileSize = 20 * 1024 * 1024`（20MB）。文档够用，宣传片基本不够（1 分钟 1080p 大约 30–80MB）。建议二选一：
- 视频单独放宽到 200MB，文档仍限 20MB；
- 或者维持 20MB，要求管理员先压缩，前端提示已经写成「建议 mp4（H.264），单文件不超过 20MB」。

另外部署时注意反向代理的请求体上限（Nginx `client_max_body_size`），否则大文件会先被网关截断，前端只能看到 413。

## 界面文案在哪

前端在接口返回 422 且信息里带「文件类型 / 仅支持 / MIME」时，会把黄色提示换成一句能照着做的话（见 `components/admin/competition-management.tsx` 的 `uploadVideo`），所以接口没放开时管理员看到的是「需要把 VIDEO 加进白名单」，不是一串校验报错。接口放开后这段提示自然不再出现。

## 后端改之前，怎么先把视频放上去

`node scripts/import-competition-video.mjs --competition <赛事ID> --file <视频路径> --title "宣传片"`

脚本把文件复制到 `public/uploads/competitions/<赛事ID>/`，并写一条 `kind = VIDEO` 的附件记录，效果与接口上传一致（不写审计日志，属于运维操作）。`--remove` 可以撤回。
