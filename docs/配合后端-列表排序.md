# 配合后端：列表排序

## 为什么要后端做

现在所有列表的顺序都写死在查询里（`lib/competitions.ts`、`lib/projects.ts` 等都是固定 `orderBy`），前端拿不到「按提交时间倒序」这种能力。

前端**不能**自己在当前页排：列表是分页的，第 1 页按时间排好，第 2 页又是另一段，翻页时顺序会跳。要做对，必须由查询在 `skip/take` 之前排好全量数据。

## 前端已经约好的参数

两个参数，跟现有的 `page`、`pageSize`、筛选参数放在同一层 query string 里：

| 参数 | 取值 | 缺省 |
|---|---|---|
| `sort` | 字段名，见下表 | 各列表原有的默认值 |
| `order` | `asc` / `desc` | `desc` |

例：`/competitions?year=2026&sort=registrationEndAt&order=desc&page=2`

非法值一律忽略、回落到默认，不要报错——用户手改 URL 不该看到 500。

## 各列表建议支持的字段

**赛事列表 `/competitions`**

| sort | 含义 | 默认 |
|---|---|---|
| `year` | 赛年 | 现有 `year desc, name asc` |
| `name` | 赛事名称 | |
| `registrationEndAt` | 报名截止（需按学生视角的窗口取值） | |
| `createdAt` | 创建时间 | |

**项目台账 `/projects`**

| sort | 含义 | 默认 |
|---|---|---|
| `updatedAt` | 最近更新 | 现有顺序 |
| `submittedAt` | 提交时间 | |
| `status` | 状态 | |
| `college` | 学院 | |

**报名审核 `/review`**

| sort | 含义 | 默认 |
|---|---|---|
| `submittedAt` | 提交时间（默认倒序，最新的在上面） | |
| `status` | 状态 | |

**审计日志 `/admin/logs`**

| sort | 含义 | 默认 |
|---|---|---|
| `createdAt` | 操作时间 | 现有倒序 |

## 实现要点

1. **白名单**：`sort` 只接受上面列出的字段，其余忽略。不要直接把参数拼进 `orderBy`。
2. **加稳定的次级键**：`[{ [sort]: order }, { id: "asc" }]`。只按状态这种重复值排序时，没有次级键会导致翻页出现重复或漏行。
3. **顺序不能反**：`orderBy` 必须在 `skip/take` 之前，否则排的是当前页。
4. **学生视角的报名截止**：赛事列表里「报名截止」不是 `Competition` 表上的字段，是 `TimeWindow` 里 `stage = SCHOOL` 那条的 `endAt`。如果这个字段不好排，可以退一步只支持 `year` / `name` / `createdAt` 三个，前端会按实际支持的字段出表头。
5. **返回结构不变**：仍然是 `{ list, total, page, pageSize }`，只是顺序变了。

## 前端这边

后端把参数接好之后，前端只需要两步：

1. 表头用 `<SortHeader>` 渲染（组件会连同箭头与 `aria-sort` 一起给），点一下写 `sort`/`order` 进 URL；
2. 页面把 `sort`、`order` 原样传给查询函数。

组件我先不做，因为现在挂上去就是个点了没反应的按钮。等接口好了，一次接上，改动集中在表头，不动查询。

## 现在的替代做法

排序接上之前，如果需要「找最近的」：

- 项目台账、审核列表默认就是按时间倒序（如果现在不是，可以先把默认顺序改成 `submittedAt desc`，这个不需要新参数）；
- 赛事列表用年份筛选代替排序。

改默认顺序是零成本的一步，要不要先做，看你们定。
