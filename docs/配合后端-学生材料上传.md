# 学生材料上传：现状与后端需求

> 面向前端/后端分工。前端已做的改动见文末，需后端配合的部分见「需求」。

## TL;DR：需要后端改的 4 处

1. 新增 `POST /api/materials/upload` —— 学生上传作品文件（**不要求 projectId**）
2. 新增 `GET /api/materials/download?fileId=` —— 带权限校验的下载
3. `prisma/schema.prisma` 新增 `MaterialFile` 表（`projectId` 必须可空）
4. `lib/apply.ts` 改两处：写入 `fileUrl` / `pptFileUrl`；提交校验从「文件名非空」改为「外链非空 **或** `fileUrl` 非空」

白名单、文件头魔数、体积上限、权限规则在第 2 节。合计约 300 行，2-3 小时。

## 一、现状核查

学生端「材料」相关其实有两个入口，性质完全不同：

| 入口 | 位置 | 能不能真上传 | 后端 |
|---|---|---|---|
| 报名表「作品（单文件）」 | `/apply` → `components/apply/work-section.tsx` | **不能**。只把 `file.name` 交给表单，文件对象当场丢弃 | 无上传接口 |
| 盖章件 | `/my/[id]` → `components/sealed/sealed-panel.tsx` | 能 | `POST /api/sealed/upload` |

### 1. 作品文件是「假上传」

`work-section.tsx` 的 onChange 只有：

```tsx
onChange={(event) => onChange({ fileName: event.target.files?.[0]?.name })}
```

`types/apply.ts` 里 `work` 明明定义了 `fileUrl` 和 `pptFileUrl`，但**全项目没有任何地方写入过这两个字段**（`lib/apply.ts:268` 只写 `fileName`）。

更麻烦的是 `lib/apply.ts:100` 的提交校验：

```ts
if (!input.work?.fileName?.trim() && !input.work?.externalUrl?.trim()) throw new ApplyError(422, "请选择作品文件或填写作品外链");
```

只看文件名非空。结果：学生随便选一个 `商业计划书.docx`，系统就认为作品已提交，而服务器上什么都没有。

### 2. 盖章件为什么只收 PDF/JPG/PNG（这是对的）

`app/api/sealed/upload/route.ts` 白名单 `pdf / jpg / jpeg / png`。这不是缺陷：盖章件的业务定义是「打印 → 签字 → 盖章 → 扫描」的成品件，Word/PPT 没有印章效力，也不该允许上传后被当成有效凭证。

所以这个入口**不建议放开格式**，前端已改成在选文件当下就给出可执行提示（而不是等后端 422）。

### 3. PPT 专区是 disabled 占位

`work-section.tsx` 里「PPT 专区」是一个 `disabled` 按钮，文案「开发中」。`pptFileName` 虽然有字段、seed 数据也写了值，但前端从来没有入口。

## 二、需求：作品文件真上传

### 推荐方案 A：独立材料接口，表单只提交 URL

**为什么不用 SealedFile 扩展**：SealedFile 是「盖章件版本流」，`@@unique([projectId, versionNo])` 会与作品文件的版本号冲突，要改成 `@@unique([projectId, kind, versionNo])`；更关键的是**报名阶段项目还没创建，没有 projectId**，而 SealedFile 强依赖 projectId。所以复用会走进死胡同。

#### A1. 新增上传接口

```
POST /api/materials/upload
Content-Type: multipart/form-data
需登录（STUDENT）

formData:
  kind: "WORK_FILE" | "WORK_PPT"   // 必填
  file: File                        // 必填
```

返回：

```json
{ "code": 0, "message": "上传成功", "data": { "fileId": "...", "url": "/uploads/materials/xxx.pdf", "fileName": "商业计划书.pdf", "mimeType": "application/pdf", "sizeBytes": 1234567 } }
```

- 落盘：`public/uploads/materials/{userId}/{uuid}.{ext}`
- 不要求 projectId（报名阶段项目尚未创建）
- 同一用户同 `kind` 重传即覆盖引用，旧文件可保留 7 天后由清理任务删除

#### A2. 白名单与上限

| 类型 | 扩展名 | 上限 |
|---|---|---|
| 文档 | pdf, doc, docx, ppt, pptx, xls, xlsx | 50 MB |
| 压缩包 | zip, rar, 7z | 50 MB |
| 图片 | jpg, jpeg, png | 20 MB |

校验三层，缺一不可：

1. 扩展名在白名单
2. `file.type` 与扩展名匹配（`docx/pptx/xlsx` 都是 `application/vnd.openxmlformats-officedocument.*.document` 系列）
3. 文件头魔数
   - Office 新格式（docx/pptx/xlsx）、zip：`50 4B 03 04`
   - Office 老格式（doc/ppt/xls）：`D0 CF 11 E0 A1 B1 1A E1`
   - rar：`52 61 72 21 1A 07`
   - 7z：`37 7A BC AF 27 1C`
   - pdf / png / jpg：沿用 `sealed/upload` 现有判断

#### A3. 报名提交时落库

`lib/apply.ts` 的 create / update 里补：

```ts
fileUrl: nullable(input.work?.fileUrl),
pptFileUrl: nullable(input.work?.pptFileUrl),
```

（`types/apply.ts` 字段已存在，无需改 schema）

#### A4. 提交校验改严

```ts
// 至少要有外链或真实上传的文件 URL，不能只凭文件名放行
if (!input.work?.externalUrl?.trim() && !input.work?.fileUrl?.trim()) {
  throw new ApplyError(422, "请上传作品文件或填写作品外链");
}
```

#### A5. 下载/预览接口

```
GET /api/materials/download?fileId=xxx
```

权限沿用 `canAccessProject`（负责人/队员/指导老师/管理员）。若文件挂在已提交项目上，`lib/sealed.ts` 里的可见性规则可直接复用。

预览建议：

- PDF / 图片 → `Content-Disposition: inline`，前端 iframe / img 直接看
- docx / pptx / xlsx / zip → `attachment`，只能下载

### 备选方案 B：把作品塞进盖章件流水

不推荐，理由见上（无 projectId、版本号冲突、语义混淆）。若短期内只能小改，可退一步：

- 报名完成、项目创建后，在 `/my/[id]` 增加「作品文件」上传区
- 仍走新接口，只是允许带 projectId

## 三、前端已完成的改动（本轮，纯展示层）

1. `components/apply/work-section.tsx`
   - 顶部加黄条：明确「只登记文件名，文件本体不会上传」，引导填「作品外链」
   - `accept` 从 `.pdf,.zip,image/*` 放宽到 `.pdf,.doc,.docx,.ppt,.pptx,.xls,.xlsx,.zip,.rar,.7z,image/*`，避免学生根本选不到自己的文件
   - 「已选择（仅本地选择，未上传）」改为「已登记：xxx」
   - PPT 占位按钮文案改为「PPT 上传待接入」，并提示先放网盘
2. `app/(workspace)/my/[id]/page.tsx`
   - 「作品文件」「PPT 文件」两个字段值后追加「（仅登记名称，未上传）」，避免详情页看起来像已交
3. `components/sealed/sealed-panel.tsx`
   - 选文件的瞬间就本地校验扩展名和 20MB 上限，给中文可执行提示（原来是等后端 422 才报错）
   - 提示文案补充「Word/PPT 源文件不具备印章效力，请另存为 PDF」
   - 当前最终版补显示文件大小

## 四、期望的后端排期

| 优先级 | 事项 | 影响 |
|---|---|---|
| P0 | A1 + A3 + A4（作品文件能传、能落库、校验改严） | 学生以为交了作品，实际没交，属于数据真实性问题 |
| P1 | A5 下载/预览 | 管理员审核时能直接打开作品 |
| P2 | A2 里 50MB 上限与压缩包支持 | 作品打包常见，20MB 不够 |

A1/A3/A4 做完后，前端只需把 `onChange` 里的 `fileName` 换成真实上传返回的 `fileUrl`，改动量在 30 行以内。
