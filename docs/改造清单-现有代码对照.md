# 改造清单：现有代码 → V3 需求

> 现有基座：`app/`，Next.js 14.2 + TS + Prisma + SQLite，89 个文件、6,585 行、13 张表、13 个页面、19 个接口。
> 结论：**脚手架和骨架可留，数据层与业务层基本重写。** 保留率约 30%，重写率约 55%，废弃 15%。

---

## 1. 一句话结论

| 层 | 判断 | 理由 |
|---|---|---|
| 技术栈与工程骨架 | **保留** | Next.js 14 + Prisma + Tailwind 完全够用，换栈纯亏 |
| 认证与权限骨架 | **保留并扩展** | jose JWT + 服务端回查角色的写法可复用，只需加角色与学生自助注册 |
| 布局与通用组件 | **保留** | 侧栏、面包屑、分页、表格、风险提示条都是资产 |
| **数据模型** | **重写** | 13 张表 → 约 22 张；`Project`/`TeamMember`/`AwardRecord` 全部变结构 |
| **导入模块** | **重写** | 现在是"获奖 Excel 单通道"，V3 要多格式 + 字段映射 + 分阶段模板 |
| 报名/审核/盖章/导出 | **新建** | 现有代码完全没有这部分 |
| 赛后模块（异常池、AI 助手、材料检查） | **冻结** | 保留代码不删，路由下线或折叠进"高级"，P2 再启用 |

## 7. 迁移顺序建议（避免边改边崩）

```
① 冻结旧模块（路由下线，代码留）→ 项目始终能 build
② 重写 schema + seed → 新库跑得起来
③ 重建 auth（三角色 + 注册）→ 能登录三种人
④ 报名表单（最大一块）→ 学生能提交
⑤ 审核工作台 → 管理员能审
⑥ 盖章闭环 + 两类导出 → 流程闭合
⑦ 赛事配置 + 窗口 + 变更申请 → 收尾
⑧ 统计看板 → 最后做
```

**关键**：每一步结束都必须 `pnpm tsc --noEmit` + `pnpm build` 通过，且旧模块保持"能编译但不暴露入口"。不要一次性删旧代码。
