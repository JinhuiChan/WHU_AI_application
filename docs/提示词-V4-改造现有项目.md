# 关键业务规则

1. **时间窗口**以 `TimeWindow` 为准；窗口外前端锁定，只能提交 `ChangeRequest`。
2. **两级审核**：学院 → 校级；驳回必填理由，退回可改后可重提，提交次数累加。
3. **状态流转**：勾选批量流转前必须先跑预检（学号不存在/状态不允许/重复），逐行报错；支持整批回滚并留痕。
4. **盖章闭环**：队员下载报名表 → 上传扫描件（≤20MB，仅 pdf/jpg/png）→ 队长下载"最终版"；管理员可批量打包，**单次 ≤100 个项目、总量 ≤500MB**，命名 `赛事_阶段_学院_项目名_队长_第N版.pdf`。
5. **两类导出**：`FORM`（可打印报名表，含签字位与公章位）、`DATASET`（可勾选字段与顺序的纯数据 Excel，导出后本地编辑）。页面不提供在线表格编辑。
6. **导入**：支持 xlsx/xls/docx/pdf，按 `stage` 绑定模板；先映射后入库；docx/pdf 解析结果必须人工确认后才写库。
7. **老师确认**不做强前置，但未确认项目在审核列表标红。

## 给团队的使用说明

**为什么保留 Next.js 而不换栈**：这次改的是**数据模型和业务流程**，不是技术底座。换栈等于把 6585 行里那 30% 可复用的资产清零，纯亏。

**为什么不一次性删旧代码**：AI 改代码最容易死在"删了一半、编译不过、然后越修越乱"。**冻结优于删除**——旧模块留在库里，能不能用以后再说，但项目始终处于可构建状态。

**为什么阶段 0 就要重写 seed**：报名系统的演示价值和数据强相关。种子数据里没有"被驳回的项目""待老师确认的项目""未上传盖章件的项目"，演示时就只能演 happy path，评审一问边界就露馅。
