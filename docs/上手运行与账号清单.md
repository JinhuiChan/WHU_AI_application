# 一、三步跑起来（新同学照做即可）

**只需要：Node.js ≥ 20.6 + Git。**

```bash
# 1. 克隆并进入项目（Windows 下命令加 .cmd，如 npm.cmd run setup）
git clone https://github.com/JinhuiChan/WHU_AI_application.git
cd WHU_AI_application

# 2. 一键初始化：首次自动安装依赖、生成 .env、建表、空库灌演示数据（可重复执行，不会清库）
npm run setup

# 3. 启动
npm run dev
```

打开终端提示的地址（默认 `http://localhost:3000`，被占用会自动用 3001）。演示账号见下一节，密码统一 `123456`。

> 说明：`npm run setup` 首次会依次做——`npm install`（已有依赖则跳过）→ 生成 `.env`（已有则不动）→ 生成 Prisma Client → 建表 → 数据库为空时灌演示数据（**已有数据不会清库**）。

## 文件会下到哪里？测完怎么删？

所有文件都在**克隆出来的那一个文件夹**里（以 `C:\Users\wwk\WHU_AI_application` 为例），不写注册表、不装全局：

| 位置 | 内容 | 大小参考 |
|---|---|---|
| `node_modules\` | 依赖 | 几百 MB |
| `.env` | 环境变量（自动生成） | 几 KB |
| `prisma\dev.db` | 测试数据库（演示数据） | 几百 KB |
| `.next\` | 编译缓存 | 几十 MB |
| `public\uploads\` | 测试上传的盖章件（如上传过） | 视文件 |

**测完删除**：先在该终端按 `Ctrl+C` 停掉 `npm run dev`，关闭终端，然后：

```powershell
cd C:\Users\wwk
Remove-Item -Recurse -Force .\WHU_AI_application
```

- 不会影响其他项目（每个 clone 有自己的 `dev.db`）；想再释放磁盘可加 `npm cache clean --force`（清全局 npm 缓存，可选）。

> **如果 clone 到的是还没有 `npm run setup` 的旧版本**（报 `Missing script: "setup"`），先用下面的等价命令；之后 `git pull` 到最新版即可改回三步：
>
> ```bash
> Copy-Item .env.example .env      # macOS/Linux: cp .env.example .env
> npm run db:generate
> npm run db:push
> npx tsx --env-file=.env prisma/seed.ts
> npm run dev
> ```
>
> 若 npm 提示 install-scripts 被拦截、随后 prisma/tsx 报找不到程序，执行 `npm run rebuild` 后重试。

## 出问题再看这里

| 现象 | 处理 |
|---|---|
| 报 `Missing script: "setup"` | 这是旧版仓库，用上面「旧版本等价命令」那 5 条，或 `git pull` 到最新版 |
| npm 提示 install-scripts 被拦截、prisma/tsx 找不到程序 | 执行 `npm run rebuild` 后重试 |
| 提示未配置 `JWT_SECRET` / `FIELD_ENCRYPTION_KEY` | 手动执行 `Copy-Item .env.example .env`（macOS/Linux 用 `cp`）后重跑 `npm run setup` |
| 页面报数据库表不存在 | 执行 `npm run db:push` |
| 想重置成演示数据 | 执行 `npm run db:seed`（⚠️ 会清空业务数据） |
| 「培养单位/申报单位」下拉只有几个值 | 新库需补 `TRAINING_UNIT`/`APPLICATION_UNIT` 字典，找维护者要同步脚本 |
| 数据库 / 上传件在哪 | 数据库 `prisma/dev.db`（复制即备份）；上传件 `public/uploads/`（不入 git） |

## 生产部署才需要动 .env

- `JWT_SECRET`：换成随机串 —— `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
- `FIELD_ENCRYPTION_KEY`：首次部署设置一次，**一旦录入真实身份证/银行卡就不要再换**，否则历史密文解不开。
- 部署前执行 `npm run build`，再用 `npm start` 启动。

1. 登录用**手机号 + 密码**，登录页可选择身份（学生/老师/管理员），身份必须与账号真实角色一致。
2. 管理员**注册**后默认 `PENDING`，必须由已有管理员在「用户管理」里审核通过才能登录。
3. 学生/老师注册即 `APPROVED`，可直接使用。
4. 一个账号可以有多个角色（学生 + 管理员等），但登录时只能以其中一种身份进入。

# 四、隐私与发布提醒

1. 本文档只收录 demo/测试账号（手机号、学号均为演示数据），可随仓库分发；**真实用户账号不写入文档**。
2. 发布前已做隐私扫描：`.env`（真实密钥）、`prisma/dev.db`（真实数据）、`public/uploads/`（盖章件/证件照）都不在 git 里；`.env.example` 只有占位值。
3. 生产环境务必更换 `JWT_SECRET`；**不要更换 `FIELD_ENCRYPTION_KEY`**，否则历史身份证/银行卡密文解密失败。
