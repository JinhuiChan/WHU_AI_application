# 一、把项目拉下来并跑起来（新同学照着做即可）

## 0. 你需要准备什么

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11、macOS、Linux 均可 |
| Node.js | **≥ 20**（推荐 20 或 22 LTS；开发机实际用的是 v24，也能跑） |
| npm | 跟随 Node 安装（≥ 10） |
| Git | 任意较新版本 |
| 网络 | 能访问 GitHub |

> 说明：**仓库根目录就是 Next.js 应用本身**（`package.json` 就在根目录），克隆后不要再进子目录找项目。

## 1. 克隆仓库

二选一（HTTPS 简单，SSH 需要你已配置 GitHub 公钥）：

```bash
# HTTPS
git clone https://github.com/JinhuiChan/WHU_AI_application.git

# 或 SSH
git clone git@github.com:JinhuiChan/WHU_AI_application.git

cd WHU_AI_application
```

## 2. 安装依赖

```bash
npm install
```

（`npm ci` 也可以，会严格按 `package-lock.json` 安装，更稳。）

## 3. 配置环境变量（必须做，否则启动会报错）

把示例文件复制成正式文件：

```bash
# Windows PowerShell
Copy-Item .env.example .env

# macOS / Linux
cp .env.example .env
```

然后编辑 `.env`，重点三个值：

```ini
DATABASE_URL="file:./dev.db"     # 保持默认即可，数据库文件实际落在 prisma/dev.db

JWT_SECRET="<自己生成一串>"        # 登录 token 签名用
FIELD_ENCRYPTION_KEY="<再生成一串>" # 身份证/银行卡加密用，必须是 64 位 hex
```

生成随机密钥（两条都执行，各生成一次，不要用同一个）：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

> ⚠️ **FIELD_ENCRYPTION_KEY 一旦开始录入真实身份证/银行卡，就不要再换**，
> 换了以后库里已有的密文会全部解不开（历史数据报废）。
> `JWT_SECRET` 换了只会导致所有人需要重新登录，影响较小。

## 4. 建表

```bash
npm run db:generate   # 生成 Prisma Client（install 后一般已自动生成，保险可跑）
npm run db:push       # 按 prisma/schema.prisma 建表 / 同步字段
```

## 5. 初始化演示数据（仅新库第一次）

```bash
npm run db:seed
```

- 会生成：赛事 1 个、演示项目 2 个（1 驳回 / 1 终审通过）、字典、报名窗口，以及下面第二节里的**演示账号（密码统一 123456）**。
- ⚠️ **`db:seed` 会清空业务数据后重建**。已经有数据的环境（比如正在用的库）**绝对不要执行**。
- 如果暂时不想跑 seed：可以注册学生/老师账号，但没有管理员就无法审核；所以新环境建议先 seed 一次。

## 6. 启动开发环境

```bash
npm run dev
```

浏览器打开终端提示的地址，通常是：

```
http://localhost:3000
```

如果 3000 被占用，Next 会自动用 3001，**以终端输出的 Local 地址为准**。

## 7. 生产模式（可选，演示/部署前跑一下）

```bash
npm run build
npm start
```

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 启动报「未配置 JWT_SECRET / FIELD_ENCRYPTION_KEY」 | `.env` 没建或不在项目根目录；按第 3 步补齐 |
| 页面 500，提示数据库表不存在 | 没执行 `npm run db:push` |
| 登录提示「手机号或密码错误」 | 密码统一是 `123456`（演示账号）；或该账号是别人注册的 |
| 登录提示「账号待管理员审核」 | 管理员注册默认 PENDING，需要已有管理员在「用户管理」里通过 |
| 「培养单位 / 申报单位」下拉只有几个值 | 新库没补 `TRAINING_UNIT` / `APPLICATION_UNIT` 字典；完整 43 个院系清单找维护者要同步脚本 |
| 数据库文件在哪、怎么备份 | `prisma/dev.db`（单文件 SQLite），**复制这个文件就是备份** |
| 上传的盖章件在哪 | `public/uploads/`（不入 git，部署/迁移时要单独带走） |
| 端口不是 3000 | 以 `npm run dev` 输出的地址为准，不要同时开两个服务 |

## 9. 登录方式

登录统一用 **手机号 + 密码**；演示账号密码都是 `123456`。账号见下一节。

## 2.4 账号相关规则

1. 登录用**手机号 + 密码**，登录页可选择身份（学生/老师/管理员），身份必须与账号真实角色一致。
2. 管理员**注册**后默认 `PENDING`，必须由已有管理员在「用户管理」里审核通过才能登录。
3. 学生/老师注册即 `APPROVED`，可直接使用。
4. 一个账号可以有多个角色（学生 + 管理员等），但登录时只能以其中一种身份进入。

# 三、隐私与发布提醒

1. 本文档只收录 demo/测试账号（手机号、学号均为演示数据），可随仓库分发；**真实用户账号不写入文档**。
2. 发布前已做隐私扫描：`.env`（真实密钥）、`prisma/dev.db`（真实数据）、`public/uploads/`（盖章件/证件照）都不在 git 里；`.env.example` 只有占位值。
3. 生产环境务必更换 `JWT_SECRET`；**不要更换 `FIELD_ENCRYPTION_KEY`**，否则历史身份证/银行卡密文解密失败。
