# 团队改进指引：在 AI 生成的 MVP 上做什么、不做什么

> 配套文档：《PRD-高校科创赛事综合管理服务平台.md》（需求真相）、《提示词-AI生成MVP.md》（AI 交付物）
> 版本：V1.0｜适用：队员 A（前端/负责人）、B（后端）、C（数据库/数据整合）、D（AI）、E（对接/测试部署）
> 阅读顺序：全员先读第 1–3 章（20 分钟），再跳到自己的那一节精读。

---

## 1. 先给判断：AI 那版一定是"能演不能扛"

AI 生成 MVP 会在**三件事上做得很好**，在**三件事上必崩**。认清这一点，团队的力气才不会花错地方。

| AI 做得好（**保留，别重写**） | AI 一定崩（**必须人改**） |
|---|---|
| 页面骨架、路由、表单、表格这些"形状" | **统计口径**：跨年聚合、重复计数、折算系数随意写 |
| CRUD 与接口的连通性 | **数据可靠性**：无事务、无来源标签、无软删、导入半成功 |
| 基础样式与响应式布局 | **可解释性**：AI 回答无出处、诊断敢给分、结论指不到条款 |

一句话原则：

> **骨架留、器官换。** 数据表、页面结构、路由与组件库全部保留；口径、权限、事务、AI 底线、移动端体验全部重做。

---

## 2. 这一版 MVP 的边界（先统一，避免各改各的）

**算交付的**（答辩现场必须能演）
看板、学院排行（可下钻）、赛事列表与详情、项目全貌与版本时间线、导入向导、异常待核实池、获奖 Excel 导出、AI 咨询（带出处）、材料规范性检查、两类账号权限。

**不算交付的**（谁中途去做，谁的进度就废了）

| 禁止事项 | 归属 |
|---|---|
| 报名、网评、评审打分、评委分配 | 明确不做（第二课堂在做） |
| 通知节点聚合、组队招募、自定义表单引擎、推荐上报 | V3，不进这轮 |
| 学分对接、教师工作量认定 | 只做导出，不做认定 |
| 电子证书、荣誉墙、消息推送、小程序 | 不做 |
| 多校 SaaS、多租户 | 不做 |
| 更换技术栈（除非全队书面同意） | 不做 |

---

## 3. 全队第一件事：冻结接口契约（B + C 主导，A 审核）

这是五个人能不能并行干活的分水岭。**接口没冻结之前，前端所有页面只能对着假数据写，后端所有实现都可能白做。**

**第 1–2 天必须产出**：`/docs/api-contract.md`，包含

1. 全部接口路径、方法、请求/响应字段（按主文档第 5 章 + 提示词接口清单）
2. 统一响应结构：`{ code, message, data }`，错误码表（401 未登录 / 403 无权限 / 422 校验失败 / 409 冲突）
3. 分页结构：`{ list, total, page, pageSize }`
4. TS 类型定义放同一个文件 `types/api.ts`，前后端共用

**规则**：契约改了必须在群里发一条"契约变更：X 接口 Y 字段 Z→W"，其他人 30 分钟内确认。**口头同意不算数。**

## 4. 分人改进清单

### 队员 A｜项目负责人 + 前端

**AI 交给你的是什么**：能点、能跑的页面，但视觉是一套默认风格，管理端信息密度不够，移动端大概率错位，看板只有图没有"讲得清的故事"。

**你的 5 个改进目标（按优先级）**

| # | 目标 | 验收标准 |
|---|---|---|
| A1 | **建立设计基线**：颜色、间距、字号、圆角、阴影写成 token（`tailwind.config` + CSS 变量），全站只引用 token | 改一处 token，全站主色/字号同步变化 |
| A2 | **管理端效率改造**：表格支持列冻结、密度切换（紧凑/舒适）、多选批量操作、键盘可达 | 200 行数据下横向滚动首列不跑；批量处置异常可用 |
| A3 | **看板讲得清**：4 张 KPI 卡支持点击下钻到项目列表；趋势图可切换"获奖数/项目数"；学院排行每行可展开加分明细 | 从任一数字点三次内到达具体项目 |
| A4 | **移动端可用**：项目全貌、AI 助手、材料检查三页在 375px 宽度下无横向滚动、按钮可点 | 真机或 DevTools 375px 截图核对 |
| A5 | **演示流程固化**：写 12 步演示脚本（对应提示词验收脚本），配一份备用截图（防现场断网） | 全队按脚本彩排一遍，卡点记录并修复 |

**作为负责人的 4 个动作（这部分比写代码更重要）**

1. **每日 15 分钟站会**（固定时间）：昨天完成 / 今天计划 / 卡在哪，每人 2 分钟，**不讨论技术细节**，会后单聊。
2. **每日一次合并窗口**（建议 18:00）：只在这个窗口合并到 `main`，其余时间各自分支。
3. **分支规范**：`feat/a-dashboard`、`fix/b-import-transaction`；PR 描述必须写"改了什么 + 怎么验证"。
4. **冲突仲裁**：同一文件两人同时改，由 A 当场指定一人负责合并，另一人改别的文件。**不要在群里争。**

**你会踩的坑**：AI 生成的组件常常"看起来一样、其实每个页面各写一套"。A1 的 token 化如果不做，两周后你会陷入"改一个按钮颜色要动 20 个文件"的地狱。

### 队员 B｜后端

**AI 交给你的是什么**：接口能通，但权限只在前端藏、导入没有事务、审计日志缺失、错误处理是 `catch(e){console.log(e)}`。

**你的 5 个改进目标**

| # | 目标 | 验收标准 |
|---|---|---|
| B1 | **权限下沉到服务端**：写操作统一过中间件校验角色；越权返回 403 而非 500 | 用普通账号直接打 POST 接口，全部 403 |
| B2 | **导入事务化**：整批失败全回滚；部分成功返回逐行明细（行号、字段、原因） | 构造含 5 类错误的文件，导入后数据库无脏数据 |
| B3 | **审计日志全覆盖**：登录、导入、入账、作废、发布结果、处置异常，每条写 `AuditLog` | 任一写操作后在日志页可查到操作人/时间/变更前后 |
| B4 | **获奖记录不可变**：`VERIFIED` 后禁止 UPDATE，只允许作废（`VOIDED` + 原因）；数据库层加约束，不只靠业务代码 | 直接用接口尝试改已核验记录，返回 409 |
| B5 | **结果发布开关**：结果默认仅管理员可见，`PUBLISHED` 后才对普通用户可见 | 发布前普通账号看不到，发布后能看到，撤销后又看不到 |

**加分项（有余力再做）**：接口限流（防截止日高峰）、导出任务异步化（大数据量不阻塞）。

**你会踩的坑**：AI 写的 "校验" 往往只校验字段非空，不校验业务（如"同一个项目同一赛事不能有两条获奖记录"）。B1/B2 的本质是**把业务规则从按钮搬到数据库入口**，这活儿必须你亲自做。

### 队员 C｜数据库 + 数据整合

**AI 交给你的是什么**：能建表、能查，但大概率缺三个字段（`sourceType`、`competitionYear`、`deletedAt`），缺两个约束（软删、唯一键），汇总查询是 `findMany()` 后在内存里算。

**你的 5 个改进目标**

| # | 目标 | 验收标准 |
|---|---|---|
| C1 | **补齐主数据字段**：`Competition.year` 独立存在、`DataSource` 横向挂所有实体、`deletedAt` 软删 | 任一记录可答"从哪来、何时同步、谁确认的" |
| C2 | **别名与归并**：`ProjectAlias` 支持项目名/报名号/队伍号；同一学号自动归并，同名不同号**不自动合并** | 造两条同名学生，系统提示而非合并 |
| C3 | **汇总查询下推到 SQL**：学院排行、年度统计用 `groupBy`/原生 SQL，禁止全表拉取再计算 | 1 万条数据下看板 ≤3s |
| C4 | **导出模板化**：获奖汇总 Excel 按学校报送口径出表（含表头、赛年、学院汇总页） | 导出文件打开即用，列头与报送表一致 |
| C5 | **赛年与届次治理**：`seriesId` 串联历届；统计接口强制带 `year` 参数，缺省报错而非全量 | 不传 year 调用统计接口返回 422 |

**另外你负责一项研究性任务**：把第二课堂与青创珈X 的**数据格式摸清**，输出 `docs/external-data-mapping.md`——对方有哪些字段、怎么映射到我们的表、哪些字段拿不到、拿不到时用什么替代。这份文档是 E 做对接的依据，也是答辩时"我们真的调研过"的证据。

**你会踩的坑**：SQLite 跑得好好的，迁到 PostgreSQL 时日期、布尔、自增主键全出问题。**从第一天就用 Prisma 的类型化查询，别手写方言 SQL。**

### 队员 D｜AI 智能模块

**AI 交给你的是什么**：一个能聊天的框，回答看起来挺像，但**没有出处、会编规则、诊断敢给分**。这一块是全队的信誉风险点——AI 乱说一句"你的项目能拿省一"，答辩现场就完了。

**你的 5 个改进目标**

| # | 目标 | 验收标准 |
|---|---|---|
| D1 | **出处强制**：检索命中才回答，答案必带「文件名 · 章节/页码 · 赛年」；未命中固定转人工话术 | 问 20 个知识库内问题，出处可核验 ≥90%；问"校长是谁"必转人工 |
| D2 | **规则引擎与模型分离**：页数、字数、章节完整性、图表编号这类**确定性判定只用规则引擎**；模型只负责解释与建议 | 关掉模型 API，材料检查的 ✓/✗ 判定仍然完整可用 |
| D3 | **黄金测试集**：50 道题（含 15 道"库里没有答案"的陷阱题），写脚本一键跑分 | 换模型或改提示词后跑一遍，通过率不低于基线；无答案转人工率 ≥90% |
| D4 | **免责与措辞**：界面固定风险条、结论附依据条款、禁止出现分数/名次/通过率 | 全局搜索"分""奖""通过率"，无违规文案 |
| D5 | **赛年优先**：同一问题多赛年答案时取最新，并显式标注适用赛年与切换入口 | 2025/2026 两版规则并存时，默认给 2026 并标注 |

**答辩专用素材（你负责口播）**：用 3 分钟讲清"我们怎么防止 AI 胡说"——出处强制 → 规则与模型分离 → 测试集与转人工率。这一段是全场最容易拿分的部分。

**你会踩的坑**：把 PDF 整篇丢进上下文。正确做法是**分块入库 + 检索命中段落**，并且保留章节号，否则出处的"章节"永远对不上。

### 队员 E｜平台对接 + 测试部署

**AI 交给你的是什么**：一个 `npm run dev` 能跑的本地项目，`npm run build` 大概率挂；没有任何测试；没有部署方案。

**你的 5 个改进目标**

| # | 目标 | 验收标准 |
|---|---|---|
| E1 | **Mock 双平台**：写一个 mock server（或 MSW/JSON 接口），模拟第二课堂（报名、网评结果）与青创珈X（组队招募）的返回，字段按 C 的映射文档 | 前端能像接真接口一样调通，切换开关一行配置 |
| E2 | **适配层落地**：真实 API 到位后只改 `providers/`，业务代码零改动；含鉴权、重试、超时、字段映射、异常降级 | 把 mock 换真接口，只改环境变量与映射表 |
| E3 | **主流程测试**：6 条端到端脚本（登录→导入→异常处置→发布→看板→导出；AI 问答；材料检查） | 每次合并窗口后跑一遍，全绿才允许合并 |
| E4 | **部署与迁移就绪**：Dockerfile + compose；环境变量外置；一键备份恢复；**完整跑一次"导出—迁移—切换"** | 新环境从零起服务 ≤30 分钟 |
| E5 | **答辩素材**：系统架构图、技术说明、测试记录表（用例数/通过率/遗留问题） | 图表在答辩 PPT 中可直接使用 |

**你会踩的坑**：`npm run build` 挂掉通常是两类——服务端组件里用了浏览器 API，或动态路由没处理 `params` 类型。**每完成一个阶段就 build 一次，不要攒到最后。**

## 5. 依赖关系与三周节奏

```
第1周：B+C 冻结契约与数据模型 ──┬─→ A 按契约改前端（先 mock）
                              └─→ E 起 mock 服务与部署脚本
        D 独立开工：知识库分块入库 + 规则引擎（不依赖后端）

第2周：A 接真接口；B 权限/事务/审计；C 汇总查询与导出；D 出处强制与测试集；E 端到端脚本

第3周：E 主导联调 → 全员修 Bug → A 固化演示脚本 → D 讲 AI 底线 → 全队彩排两遍
```

| 周次 | 里程碑判据 |
|---|---|
| 第 1 周末 | 契约冻结、页面能跑、mock 接口可调、知识库能检索 |
| 第 2 周末 | 全部功能可跑通一遍，无阻断性 Bug |
| 第 3 周末 | 12 步演示脚本零卡顿，build 通过，部署可复现 |

## 6. 五条团队纪律（比技术更重要）

1. **契约变更要广播**：接口改了不说，等于让别人白干半天。
2. **只在自己的分支动**：`main` 只能由合并窗口更新，谁破规矩谁负责回滚。
3. **不许"顺手重构"别人的模块**：要改先提，改完写清原因。
4. **每人每天一条进度**：完成什么、卡在哪，一句话即可。
5. **Bug 分级**：阻断演示的当天修；影响体验的进清单；锦上添花的直接砍。

---

## 7. 质量红线（答辩现场不能出的事）

| 红线 | 负责 | 出事后果 |
|---|---|---|
| AI 编造规则或给出分数/名次 | D | 全场信任崩塌，最致命的失分 |
| 看板数字与台账对不上 | C | 一本账立不住，整个定位被推翻 |
| 普通账号能改数据 | B | 演示时被评审当场试出来 |
| 断网或刷新后数据丢失 | C/E | "演示型产品"标签坐实 |
| 现场 500 / 白屏 | E | 前面做得再好也白搭，必须准备离线录屏兜底 |

## 8. 一句话给每个人

- **A**：你的价值不在画得好看，在于让评审在 12 步之内看懂这个系统。
- **B**：你守的是"谁能改数据"这条线，这条线破了，产品就只是玩具。
- **C**：你守的是"数字对不对"这条线，全院排行错一位，老师就再也不会打开它。
- **D**：你守的是"AI 别说瞎话"这条线，这条守住了，你们比 90% 的同类作品强。
- **E**：你守的是"到时候能不能打开"这条线，答辩那天，全场只看你部署的那个链接。
