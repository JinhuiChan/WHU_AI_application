# 演示数据说明（800 学生 / 50 教师 / 240 个国创赛报名项目）

> 本目录内容由脚本生成，**请勿手工改名**（文件名与赛事一一对应）。
> 存在两份，内容一致：
> - **仓库内**：`mvp/demo数据/`（随 Git 提交，别人克隆后即可用）
> - **仓库外工作副本**：`高校科创平台/demo数据/`（由 `npm.cmd run demo:generate` 生成，不受 Git 管理）
> 用 `npm.cmd run demo:sync` 把仓库外的生成结果同步到仓库内再提交。
>
> 本套模拟数据**全部归属「中国国际大学生创新大赛」**（2026 校赛）；种子数据里另有挑战杯、百珈争创两个赛事，本套数据不涉及。

## 一、文件清单

| 文件 | 用途 | 内容 |
|---|---|---|
| `01-学生账号清单-800人.xlsx` | 账号备查 | 800 名学生：学号、姓名、登录手机号、密码、学院、专业、培养阶段、年级、邮箱 |
| `02-教师账号清单-50人.xlsx` | 账号备查 | 50 名教师：工号、姓名、登录手机号、密码、学院、职称、邮箱 |
| `03-导入-中国国际大学生创新大赛-2026校赛-240项.xlsx` | 可导入平台的报名数据 | 240 个项目 + 23 条成员/老师续行 = 263 行 |
| `04-Word导入示例-单成员单老师.docx` | 格式演示（非正式数据） | 演示 Word 能识别的格式；受解析限制只含 2 个项目、每项目 1 成员 1 老师，正式导入请用 03 的 xlsx |

导入文件包含两个工作表：`报名数据`（平台读取第一个工作表）和 `导入说明`（人工查阅，平台忽略）。

### 格式支持与限制（xlsx / Word / PDF）

| 格式 | 平台是否支持 | 实际能否导入本套数据 | 说明 |
|---|---|---|---|
| `.xlsx`（推荐） | ✅ | ✅ **可以** | 读第一个工作表；多行单元格（1 格多人）、续行都支持；自动映射、无需人工确认 |
| `.docx` | ✅（代码支持） | ⚠️ **受限** | 解析结果为「纯文本 + TAB 分列」，**不能用 Word 表格**；行首 TAB 会被去掉，因此**不能有续行**；单元格内换行会被拆成新行，因此**每个项目最多 1 名成员 + 1 位指导老师** |
| `.pdf` | ✅（代码支持） | ❌ **基本不可用** | PDF 文本层没有制表符，列名会连成一整列（自动映射 0 个字段），无法保存映射；扫描件无文本层直接解析失败 |

> Word/PDF 上传后平台会标记 `requiresConfirm=true`，必须在映射页勾选「我已逐行核对解析文本与映射预览」才能保存映射。

## 二、快速开始（新克隆仓库后）

```powershell
cd <仓库根目录>            # 即 mvp 目录（package.json 所在目录）
npm.cmd run setup          # 首次：安装依赖、生成 .env、建表、灌基础演示数据
npm.cmd run demo:all       # 一键：800/50 账号 + 生成数据 + 导入 240 项目 + 绑定账号
npm.cmd run dev            # 启动，浏览器打开终端提示地址
```

`demo:all` 依次执行：

1. `db:seed:accounts`：写入 800 学生 + 50 教师账号（幂等）；
2. `demo:generate`：生成演示数据到仓库外 `../demo数据/`；
3. `demo:sync`：同步到仓库内 `demo数据/`；
4. `demo:import`：走平台导入管线，把 240 个项目写入数据库；
5. `demo:link`：全量绑定负责人/成员/指导老师到账号。

完成后数据库状态与本地演示环境一致：872 个账号（另含 1 管理员 + 18 基础学生 + 3 基础教师）、258 个项目（240 导入 + 18 基础）。

## 五、历史报名与账号的关联

数据导入只按学号/工号保存文本，不会在导入时直接关联账号。平台现在的规则是：

- **学生：注册或登录时自动关联**——按学号把 `TeamMember.personNo` 的历史记录绑定到账号，并把其作为负责人的项目补上 `ownerId`；注册后直接能看到"我的项目"（登录时再补一次兜底）。
- **教师：登录时自动关联**——按工号绑定 `Teacher.userId`；即使不绑定，教师端"指导项目"本身也按工号匹配，可直接确认指导关系。
- 也可执行 `npm.cmd run demo:link` 一次性全量绑定（脚本只填空值、可重复执行）。
- **800 名学生全部覆盖**：每个项目 1 名负责人（240 人互不重复）+ 2~4 名成员；50 名教师全部有指导项目。

> 想验证"注册即看到"：注册一个学号出现在 `03` 表格里、但数据库里还没有账号的学生，登录后「我的项目」即可看到对应项目。

## 六、数据口径

- 赛事：**中国国际大学生创新大赛（2026，国家级）**，共 240 个项目。
- 赛道：`国内项目`、`海外项目`、`青年红色筑梦之旅赛道`、`产业赛道`（与赛事详情里的赛道字典一致）。
- 组别/类别：完全取自各赛道挂载的字典，「赛道」列写作 `赛道/组别/类别`。
- 人员对应关系：240 名负责人互不重复；800 名学生全部至少参与 1 个项目（其中 20 人参与 2 个）；50 名教师共 320 条指导关系；约 45% 项目由负责人兼任奖金领款人。
- 字段格式：
  - 「成员」列：每行一名成员，英文逗号分隔、多行换行分隔 —— `是否校内,姓名,学号,培养阶段,培养单位,专业,性别,民族,入学年份,毕业年份,手机号,邮箱`
  - 「指导老师」列：每行一位老师 —— `是否校内,姓名,工号,性别,手机号,学校,单位,职称,邮箱`
- 入库后状态：项目 **待学院审核（PENDING）**，指导关系 **待确认（PENDING）**。
- 数据全部为模拟数据，手机号/学号/工号/邮箱均为虚构。

## 七、重新生成与重置

| 场景 | 命令 |
|---|---|
| 重新生成仓库外演示数据（覆盖同名文件，并清理上版遗留导入文件） | `npm.cmd run demo:generate` |
| 同步仓库外生成结果到仓库内 `demo数据/` | `npm.cmd run demo:sync` |
| 重建账号（幂等） | `npm.cmd run db:seed:accounts` |
| 一键重建演示数据（账号 + 生成 + 同步 + 导入 + 绑定） | `npm.cmd run demo:all` |
| 想从头再来（清库 + 基础数据 + 账号 + 数据） | `npm.cmd run db:push --force-reset` → `npm.cmd run db:seed` → `npm.cmd run demo:all` |

> 注意：同一赛事下项目名称必须唯一，同一批数据重复导入会因项目名重复而失败；`demo:import` 会跳过已成功导入过的同名文件。
